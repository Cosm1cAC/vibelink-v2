# 群聊工作系统：方案与阶段验收

参考 dsh-superagent-prototype `8c32a9dc5d72c033816c6a8110b37f40cf94fba4` 的持久任务、主脑路由、执行者所有权、恢复及低打扰原则。实现适配 VibeLink Hub/官方 CLI，不引入 DSH 执行环境或 Cindy 云端依赖。

## 第一阶段：Hub 是唯一任务状态源

本次实现范围：

- 手机提交明确请求；群消息是交流记录，Work 是可恢复的工作记录，Step 是一次 Agent 操作。
- 主脑按需返回 1–4 步结构化计划；Hub 校验成员、步骤数、模式、验收条件。普通请求可以只派一人。
- 执行 → 只读审校 → 主脑验收；验收不通过回原执行会话返工一次，仍不满足则交用户决定。
- 用户明确点击任务“追问”才归入原 Work。运行中追问排队，完成后追问复用原执行者会话；普通发送产生新 Work。
- Hub 持久保存输入、计划、冻结的 Bot/模型/权限/目录、操作编号、会话、证据、结果及消息投影。手机退出不影响推进。
- Android 应用级 outbox 先落盘 requestId 再提交；网络丢回包和进程重启使用同编号恢复，不重复新建任务。
- Agent 先同步落盘操作意图，再启动 CLI，最后保存原始接收回包。重复操作回原收据；意图存在但结果不明时挂起，不重新运行工具。
- Hub 重启恢复未完成任务，也恢复尚未重新登录的内测租户任务。已确认派发的步骤只查询原会话。
- 输入和结果消息直接从同一账本投影，避免“已保存任务但没发群消息”的双写窗口。日常只显示状态/结果/必要问题，步骤展开查看。
- 全局最多 2 个 Work 并行，每个开发空间或内测账号内 Work 串行；本期“多人分工”按工位顺序执行，避免同时修改共享工作目录。
- 只接收用户 client/admin 请求；Bot/Agent 不能给自己签发新的群任务权限。模型输出只提出计划，不授予权限。原模型计量、每用户配额、MXC 内测隔离继续生效。

验收：手机离页/重启不丢任务；Hub 在派发与回包之间重启不重复调用；跨用户不能追问/取消任务；已完成结果能回到原群；审校缺口触发原会话返工并再次验收；模型或权限中途改变时挂起。

### API 与存储

- `POST /api/bot-groups/{groupId}/work`：`requestId, text, mode(auto|parallel|relay), botIds?, replyToWorkId?, files?, skillIds?, delegationMode(work|consult)`。
- `GET /api/bot-groups/{groupId}/work`：任务轮询投影，不返回内部提示词、角色快照、base64 附件。
- `POST /api/bot-groups/{groupId}/work/{workId}/actions`：`action=cancel|retry`。重试恢复原操作；`retryable=false` 时应使用追问补充信息。
- 原 `GET /api/bot-groups/{groupId}/messages` 合并旧消息与 Work 消息，无需迁移旧群历史。
- 每个版别/租户自己的 `group_work.json`，同步原子写入，写失败不提交内存状态；损坏账本拒绝启动，不能悄悄变成空任务队列。
- 每个输入最多 8 个附件、12 MB 编码体；账本最多 500 个 Work、64 MB。达到上限明确拒绝，不静默删除未决任务。
- Agent 0.3.0 起支持操作收据；Hub 依据实际在线心跳版本校验，旧 Agent 不能忽略 operationId 后接任务。

限制：不宣称外部副作用 exactly-once。Agent 在落盘意图后、落盘回包前崩溃，可能已经产生副作用，此时停止并保留不确定状态。取消停止后续派发并请求中断已知会话，不回滚已发生的工具/外部操作。OS 进程退出后恢复的是工作状态和会话，不是复活旧进程。发版前通过实际 CLI、重启/丢包模拟及两版 Android 构建验证。

### 已完成的验证

- Hub 39 项、Agent 38 项测试通过，包含回包丢失后重启、取消时只读查询收据、租户隔离、写盘失败、第三方成员越界、正在执行时权限收紧、跨页轮次匹配、只读追问不提升写权限，以及中途成员提问后续接该成员并继续剩余计划。Agent 另有 3 项 opt-in 测试默认忽略。
- 临时 Hub + 生产 Agent 传输/处理器 + 官方 Codex CLI + 真实 Magpie/DeepSeek 完成一轮工作；随后重启 Hub、Agent，再追问同一任务，续接同一个执行会话。最终复验 8 次上游请求，98,387 tokens（缓存包含在输入中），缺失用量 0；输入消息仅 2 条，没有重复消息。没有启动工具或修改项目文件。
- Android dev/beta 均完成编译及 10 项任务/路由/会话聚焦测试；发版额外运行模型政策、更新安装和 Release 配置保护测试。

## 第二阶段：更清晰的范围与跨任务治理（Hub 0.3.0 / Agent 0.4.0）

负责人：Hub/Agent，手机与桌面共用接口。本阶段已实现后端接口，桌面和手机的治理面板属于下一阶段。

- 每个 Work 保存用户签发的 mandate：主体、原输入编号/摘要、版本、允许的成员/模型/Agent/设备/配置目录、只读边界、原完成标准。模型细化不能替换或降低用户标准；缺少可选细化时保留原标准。取消撤销授权和未使用的模型能力凭证。
- 执行者可返回 `{"handoff":{"reason":"缺口","requestedBotIds":[],"requestedWorkspace":""}}`，Hub 暂停，绝不按模型建议自动扩大范围。原任务追问继续受原 mandate 限制；用户明确提交新 Work 可用 `parentWorkId` 关联同组、同主体的旧任务。
- Agent 先只读解析真实设备及规范工作目录，Hub 以物理设备和目录层级加持久 lease；同目录/父子目录有写操作时互斥，只读可共享。Windows 主机别名统一，租户名不能掩盖真实路径冲突。Git 仓库保守锁定仓库根目录；工作树初始化本身也有持久操作收据。
- 每个 Hub 的租户共用一份 lease store；独占文件锁阻止两个 Hub 同时覆盖同一份 store。lease 带递增 fencing generation；陈旧 token 不能提交结果或释放新持有者。
- 全局最多 4 个 Work 运行，不同工作目录可并行；同一 Work 内仍按步骤执行。冲突排队而非重复派发。租户实际工作目录经过读取隔离后独立；开发版和内测版继续使用各自数据、Agent 运行档。
- 接到中断回包或看到最终消息都不足以释放目录。Agent 必须确认该执行器已无排队/在途运行、所有登记子进程已回收，Hub 才接受完成/停止证据。崩溃、超时或失联保留不确定占用，不使用 TTL 猜测释放。升级前未确认的旧操作只查收据；恢复目录屏障后重试也不重新派发。
- 每任务 DeepSeek 请求数、真实/缓存 token、缺失用量估计、预留额度和模型调用耗时持久计量。任务预算与每日用户额度一起原子检查，取消不能逃避已发生用量；GPT 订阅用量标为 `not_reported`，不伪报为零。群任务管理的底层会话不能经私聊入口绕过任务预算续写。
- CLI 本轮失败使用带原任务 marker 的 `turnError` 返回；429/进程错误暂停任务，不进入审校，不把错误文本当完成证据。Agent 重启后可从原 CLI 记录恢复错误；旧会话上一轮的错误不能中断新的追问。
- 搜索、显式归档和完整 JSON 导出已实现。先同步保存归档全文和附件，再压缩活动账本；保留结果、消息、会话、输入去重及用量审计。活动任务上限 500、64 MB，归档释放活动名额，不自动删除未决任务。

### 新增接口与迁移工具

- 提交 Work 可加 `budget: {"tokens": 200000, "requests": 30}`；0 表示不额外限制该维度，仍受用户额度约束。已有任务沿用原预算。
- `GET /api/bot-groups/{groupId}/work?q=关键词&archived=true`：按标题/输入/结果检索，附带 `billing`；默认隐藏归档。
- `POST /api/bot-groups/{groupId}/work/{workId}/actions`：增加 `action=archive`，仅允许任务所有者归档已结束且无未明执行/占用的任务。
- `GET /api/bot-groups/{groupId}/work/{workId}/export`：所有者导出原输入/附件、授权、完整步骤和用量。导出含用户内容，应按任务数据保存。
- `python tools/export-work-sqlite.py <一致性备份目录> <新私有快照.sqlite>`：保留归档全文及 lease/usage 元数据，建立索引并校验记录摘要和 SQLite integrity。拒绝覆盖已有文件。这是离线审计/迁移快照，**线上持久化仍为原子 JSON，尚未切换数据库**。

边界：lease 管理本 Hub 群任务经认证 Agent 解析的目录，不覆盖用户手动编辑、独立私聊或其他程序；同仓库在不同物理设备上的副本是不同资源。生命周期证明覆盖执行器登记的进程，不宣称控制任意脱离的后台守护进程。群任务默认关闭工具网络，保留原生 Git 元数据保护；提交/推送、外部发布需要后续受控发布入口，不能靠放宽沙箱解决。Windows 群任务显式使用官方 MXC，失败即停，不退回无隔离执行。

Windows 内测工具可只读访问宿主发现的 PowerShell 7/Python 安装叶目录，以便原生沙箱启动这些运行库。发现逻辑不接受模型或手机指定的目录，拒绝盘根、用户根目录及凭据/会话/工作区目录，也拒绝把安装目录 junction 重定向到其他数据。没有开放整个 AppData 或用户目录。真实 MXC 已验证 PowerShell 7 和 Python 在测试工作区写文件成功，读取同级外部测试文件均被拒绝。

验收证据：Hub 59 项、Windows Agent 52 项及 macOS Agent 52 项测试通过（Agent 各 3 项需显式开启的真实/子进程测试默认忽略）。包含跨群/父子目录争用、过期 fencing、重启持锁、旧派发只查收据、取消不冒认进程退出、原验收保留、归档完整导出、按任务预算预留与原用户计量、失败轮次归属。真实执行验证见下方发布记录。

## 第三阶段：统一 Cindy 桌面入口与通知

负责人：桌面桥接与 Hub。

- Cindy 桌面读取同一 Hub Work/消息投影，提供计划、执行细节、追问、取消、验收视图。
- 复用 Cindy 原有 group/session/plan/outbox 组件与本地执行能力，通过 adapter 接入 Hub；不另外维护第二套权威任务账本，不依赖 Cindy 云端登录才能完成本地任务。
- 外部渠道发送采用持久 outbox、确定消息键、投递结果和失败重试；收件 ACK 与任务完成独立。
- 先完成[统一登录](login-system.md)：手机确认桌面登录时为同一主体签发独立设备会话，旧手机 `client_<tokenId>` 主体保留，新本机配对归 `owner`，内测继续以同一 tenant 为主体。桌面可用同主体的会话操作原 Work，无需伪造 `meterIdentity`、复制手机凭据或隐式管理员代办。
- 最小落点是独立的 typed HubWork adapter、Main/preload 白名单桥、renderer 的 Hub 任务镜像 store/视图和独立 outbox；复用现有桌面桥与去重模式，不能把 Hub Work 送进 Cindy 原 bot-group 执行器再执行一次。outbox 命名空间包含 Hub 地址、版别和主体，稳定 requestId 对应不可变输入。

验收：手机、桌面看到相同 Work/Step/会话；任一端重启不重复派发；通知失败不把任务当完成或生成重复任务。

## 第四阶段：有明确规则的主动运行

负责人：Hub 策略、审批、配额系统。

- 引入 off/observe/auto；默认 observe，只记录建议，不自动执行巡检、GitHub 事件或其他外部触发器。
- 显式用户请求始终按用户授权处理；自动运行必须匹配已保存的授权规则，计入原用户配额。
- 触发器、判断记录、规则版本、投递去重、降噪和一个必要问题的交互独立建模。

验收：仅“看起来有用”的事情不会自动开工；撤销规则立即阻止新派单；重放事件不会重复创建工作；通知只在结果、决策或阻塞时打扰用户。
