# 群聊主动运行：观察首批

桌面「Hub 工作区」展开「主动运行」，选择群。每个已登录账号管理自己的规则，只观察自己拥有的 Work；同群其他账号的任务不受这些规则影响。本批提供 `observe`（记录建议）和 `off`，默认 `observe`。`auto` 在界面和后端都不可用。

观察记录不会调用模型、创建或重试 Work、执行工具、运行巡检、消费模型 token，或发送系统/外部通知。原有明确提交任务的入口保持原授权行为。建议只是审计记录，不代表已经派单、执行或完成工作。

## 规则与判断

规则须由用户填写名称并选择 `completed`、`failed`、`needs_input` 状态，明确保存后生效。编辑同一规则产生新的不可变版本，旧版本保留且被替代；撤销保留版本和撤销时间。匹配判断保存事件键、Work 观察序号、规则编号与版本，以及 `matched`、`off`、`revoked` 理由。

策略和规则修改共用 `expectedRevision`。同一账号的多个窗口同时修改时只接受当前版本。冲突或写回执不明须刷新核对，界面不会自动重试。账号/群切换、会话到期与退出撤销旧请求，旧回包不能覆盖新界面。主动运行使用普通用户 client 凭据，不能借内测管理凭据访问其他人的规则。

## 观察与恢复边界

Hub 后台读取已经持久化的 Work 状态快照，无需桌面保持打开。每个 Work 新增独立单调的 `observationRevision`，与评审轮次分开；评审轮次可能在追问时重置，不能用于事件去重。首次建立基线、新规则版本与重新开启不会补发历史建议。

这是快照采样，不是完整事件流；扫描之间的瞬时中间状态可能不会被记录。判断时间表示记录时间。相同账号、群、Work 观察序号及状态对应稳定事件键，再结合规则编号/版本生成判断键。进度和判断在同一原子提交中持久化，重放、并发扫描和重启不会重复记录。写入失败不推进进度，损坏账本拒绝加载，不当作空账本。

`automation.json` 按 Hub issuer、版别、用户、群隔离。每份账本最多 128 个作用域、每作用域最多 256 个规则版本、10,000 个事件、50,000 个判断，同时受 16 MB 文件上限约束，其中为关闭/撤销等控制变更预留 4 MB，观察写入可能更早暂停；达到任一边界会明确暂停并保留未处理进度，不静默丢记录。界面只展示最近 200 条判断，不提供完整历史查询或自动清理。容量暂停是闭锁状态，本批无清空或隐式复位入口，需要后续明确的维护/迁移流程；暂停期间仍可关闭和撤销。`lastScanAt` 是最近实际处理时间，不作为实时在线心跳。

## API

`GET /api/bot-groups/{groupId}/automation` 返回 `groupId`、`policy {mode,revision}`、规则历史、最近判断和 `observer` 元数据。`observer.coverage=latest_work_snapshot`；容量问题明确返回暂停标记，持久失败返回 503，不返回假成功。

同路径 `POST` 接受以下命令，身份来自已验证会话，不能从请求指定 owner：

```json
{"action":"setMode","mode":"off","expectedRevision":0}
{"action":"saveRule","ruleId":"failure-review","label":"失败后建议复核","statuses":["failed"],"expectedRevision":1}
{"action":"revokeRule","ruleId":"failure-review","expectedRevision":2}
```

成功返回完整当前快照和递增的策略版本；版本冲突返回 409。不能把超时当作未保存证明。外部事件源、一个必要问题的交互、带预算的自动派发及通知降噪留给后续批次，未在本批启用。
