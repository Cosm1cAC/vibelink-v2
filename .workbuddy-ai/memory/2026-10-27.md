## 二、magpie 配置同步（PC ← 笔记本）

### 配置在哪

`~/.config/magpie/`：`providers.json`（providers + groups）、`logins.json`（订阅账号 OAuth）、
`plugin-auth.json`（插件类账号凭据，按槽位 key 存）、`settings.json`、`applied.json`（各 agent 绑定）、
`library.json`、`plugins.json`。运行态在 `~/.cache/magpie/`（`agents-state.json` 等）。

### 三条硬知识（踩过）

1. **magpie 不热加载配置文件**。跑着的实例把状态放内存，CLI（`magpie providers`）读的是内存不是磁盘。
   直接改 JSON 必须重启 magpie 才生效；而且重启前它可能用内存状态回写文件。
2. **别从沙箱里 `Start-Process` 拉起 magpie**。沙箱 shell 带 `HTTP_PROXY=http://127.0.0.1:65006`，
   子进程继承后所有上游都 `ECONNREFUSED`（表现为网关 502 `upstream connect failed ... 10061`），
   看起来像配置坏了其实是网络被沙箱拦。正确做法：`Start-Process explorer.exe "…\magpie.exe"`，
   借 explorer 在用户会话里拉起，脱离沙箱进程树。
3. **插件账号的凭据在 `plugin-auth.json` 的槽位里**，`logins.json` 只存 `home: "workbuddy-ai#eruxi7"` 指向它。
   只搬 `logins.json` 条目 → magpie 启动时判定为孤儿并**静默删除**。

### 验证

```
curl /v1/chat/completions model=workbuddy-ai/deepseek-v4.1-flash   → 200 正常出字
curl /v1/messages       model=claude/claude-haiku-5-5              → 200 "OK"
magpie accounts → claude / damenashojobronya 都在
```

### 一个坑（值得记）

claude 的 OAuth 条目第一次合并后被标 `lapsed: "Claude Code is no longer signed in"`，provider 显示未登录。
**token 两边 md5 完全一致**，说明不是拷贝过期。删掉 `lapsed`/`held` 两个字段重启后恢复正常并实测可用 ——
这两个字段是 magpie 自己的失败标记，跟着文件一起搬过去会「自我实现」成登出状态。
