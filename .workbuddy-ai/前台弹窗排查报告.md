# 前台命令行弹窗排查报告（2026-10-25）

## 现象

每隔约 60 秒，一个命令行窗口弹到前台约 0.9 秒后消失，打断游戏/全屏应用。

## 根因

计划任务 **`PcProxyFailover`** 的动作是直接执行 `powershell.exe`：

```
C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe
  -NoProfile -WindowStyle Hidden -ExecutionPolicy Bypass
  -File "C:\Users\22771\bin\pc-proxy-failover.ps1"
```

触发间隔 `PT1M`（每 60 秒一次，登录时也触发一次）。

关键点：`-WindowStyle Hidden` **挡不住**窗口出现。这台机器的默认终端应用是
Windows Terminal，`powershell.exe` 启动时 `conhost` 会把控制台委派给
`WindowsTerminal.exe`，终端窗口先创建、先抢前台，然后 `-WindowStyle Hidden`
才把 PowerShell 自己的窗口藏起来——但终端窗口已经弹出来了。时序上是：

```
conhost.exe 起来 → OpenConsole.exe -Embedding → Windows Terminal 窗口显示并抢前台
→ ~0.9 秒后 PowerShell 隐藏/退出 → 前台还给原窗口
```

`-WindowStyle Hidden` 只作用于 PowerShell 进程自己的窗口，管不到被委派的终端宿主。

## 取证过程

1. 轮询 `GetForegroundWindow()` + 枚举所有可见顶层窗口（每 60~90 ms 一次），
   记录窗口类名、标题、归属进程、父进程链。
2. 结果非常干净：每 60 秒整（`:49`~`:50` 秒）出现一次
   `class=CASCADIA_HOSTING_WINDOW_CLASS` 的 Windows Terminal 窗口，
   父进程链是 `WindowsTerminal.exe <- svchost.exe[1132] <- services.exe`
   ——由任务计划器通过 `svchost` 拉起，不是任何用户程序。
3. 同一条链上 `powershell.exe <- svchost.exe[2836] <- services.exe`
   的命令行正是 `pc-proxy-failover.ps1`。
4. 对照组：同一时刻 `MetricsHubWatchdog`（`PT2M`，动作是
   `wscript.exe hub-watchdog.vbs`）运行，**只产生 wscript → pwsh → curl，
   没有任何可见窗口**。说明"直接执行 powershell.exe"才是元凶。

A/B 对照实验（`ab-test.ps1`），同一个后台脚本两种启动方式：

| 启动方式 | 前台时间线 |
|---|---|
| 直接 `Start-Process powershell.exe -WindowStyle Hidden` | 0.34s 起 Windows Terminal 抢前台，1.27s 才还给游戏（约 **0.93 秒**） |
| `wscript.exe launcher.vbs` | 全程无变化，游戏一直在前台 |

## 修复

新增 `C:\Users\22771\bin\pc-proxy-failover.vbs`：由 wscript（GUI 宿主，
不分配控制台）以窗口样式 0 拉起 PowerShell，完全不创建窗口。

```vbs
Dim sh, ps, script
Set sh = CreateObject("WScript.Shell")
ps = sh.ExpandEnvironmentStrings("%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe")
script = Replace(WScript.ScriptFullName, "pc-proxy-failover.vbs", "pc-proxy-failover.ps1")
sh.Run """" & ps & """ -NoProfile -ExecutionPolicy Bypass -WindowStyle Hidden -File """ & script & """", 0, False
```

任务动作改为（需要管理员，用 `Set-ScheduledTask`；`schtasks /Change` 会卡在
"输入运行密码"提示上）：

```
Execute: C:\WINDOWS\System32\wscript.exe
Args   : "C:\Users\22771\bin\pc-proxy-failover.vbs"
```

原任务定义已备份：`C:\Users\22771\bin\PcProxyFailover.original.xml`

### 为什么宿主写绝对路径

本机 `HKCU\Software\Microsoft\Windows\CurrentVersion\App Paths\powershell.exe`
指向 PowerShell 7 的 `pwsh.exe`，脚本里写裸名 `powershell.exe` 会被劫持成
`pwsh`（`hub-watchdog.vbs` 就是这个情况，功能正常但宿主不是文档写的那个）。
这里显式用 `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`。

## 验证

- 修复后连续 200 秒（覆盖 3 个完整触发周期）前台零切换，游戏一直保持前台。
- 任务 `LastTaskResult=0`，`LastRun` 每分钟正常推进。
- 脚本功能未受影响：状态文件 `pc-proxy-failover.fails` 的 mtime 每分钟继续更新。

## 复现/复测脚本

`.workbuddy-ai/` 下：

- `flash-watch.ps1` —— 通用取证器：新进程（含命令行、父进程链）+ 新可见窗口 +
  前台切换（含上一个窗口的停留时长）。`-Seconds N` 控制时长。
- `ab-test.ps1` —— A/B 对照：`-Mode task` 复刻任务计划器的直接执行，
  `-Mode vbs` 走 wscript，对比前台时间线。
- `fix-task.ps1` —— 提权改任务动作（写 `fix-task.result.log`）。

## 以后加常驻/定时任务的做法

任务计划器里**不要**直接把 `powershell.exe` / `cmd.exe` / `.cmd` / `.bat`
作为动作——哪怕加了 `-WindowStyle Hidden`。统一走：

```
wscript.exe "<某个 .vbs>"
```

vbs 里 `WScript.Shell.Run "...", 0, False`（0 = 隐藏窗口）。

本仓库里 `metrics-hub`、`macos-socks-proxy`、`opencode-mesh`、`yto-portal-auth`、
`rshell` 的安装脚本都已经是这个写法；`wproxy` 的 `WProxy` 任务还是直接执行
`pwsh.exe -WindowStyle Hidden`（`Hidden=true` 只影响任务计划器自身 UI，
不影响窗口），只是它登录才触发一次，平时看不到闪窗，所以没动。
